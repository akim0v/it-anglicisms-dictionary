# ТЗ: одностраничный сайт «Баг или ошибка? Словарь IT-англицизмов»

Oct 1, 2026 · @Akim

## Цель и аудитория

Сайт — практический продукт проекта «Англицизмы в речи IT-специалистов»: интерактивный словарь из 36 IT-англицизмов, который показывает их значение, происхождение, русские формы и конкуренцию с русскими аналогами.

**Аудитория:** преподаватель русского языка, одногруппники, комиссия на защите. Сайт открывают по ссылке с ноутбука во время презентации и с телефона после неё.

**Главная задача страницы:** за минуту показать ответ на вопрос исследования — какие англицизмы побеждают русские аналоги и насколько глубоко они вошли в русскую грамматику.

**Что сайт не делает:** нет авторизации, базы данных, серверной логики и редактирования словаря из интерфейса. Все данные лежат в одном файле в репозитории.

## Стек и версии

Сайт строится на Nuxt 4 и Nuxt UI 4 и собирается в статические файлы. На момент написания актуальны Nuxt 4.5 и [Nuxt UI 4.11.2](https://nuxt.com/raw/changelog.md) (22 сентября 2026); ставить последние версии 4.x.

| Что | Выбор | Зачем |
| --- | --- | --- |
| Фреймворк | Nuxt 4, TypeScript | одна страница, статическая генерация |
| UI-библиотека | Nuxt UI 4 (Tailwind CSS 4, Reka UI) | готовые доступные компоненты, тёмная тема |
| Иконки | Iconify через Nuxt UI, набор Lucide | иконки в формате `i-lucide-*` |
| Шрифты | `@nuxt/fonts` (ставится вместе с Nuxt UI) | Unbounded для заголовков, Golos Text для текста — оба с кириллицей |
| Данные | `app/data/words.json` + тип в `app/types/word.ts` | без базы данных и API |
| Пакетный менеджер | pnpm | быстрее npm, стандарт экосистемы Nuxt |
| Хостинг | Vercel | бесплатный тариф, деплой из GitHub |

**Правила Nuxt UI, которые нужно соблюдать:** всё приложение обёрнуто в `<UApp>`; стили подключены через `app/assets/css/main.css` с `@import "tailwindcss";` и `@import "@nuxt/ui";`; цвета задаются через `app.config.ts`, а не хардкодом в компонентах.

**Помощь для Claude Code:** у Nuxt UI есть официальный [MCP-сервер](https://ui.nuxt.com/docs/getting-started/ai/mcp) с документацией компонентов. Подключить его до начала работы:

```bash
claude mcp add --transport http nuxt-ui https://ui.nuxt.com/mcp
```

## Структура страницы

Одна страница `app/pages/index.vue` из восьми секций; навигация в шапке ведёт к секциям по якорям. Каждая секция — отдельный компонент в `app/components/sections/`.

| Секция | Якорь | Содержание | Компоненты Nuxt UI |
| --- | --- | --- | --- |

| Главный экран | `#top` | заголовок «Баг или ошибка?», подзаголовок, три цифры: 36 слов, 34 склоняются, 15 видовых пар; кнопки «Открыть словарь» и «Как мы исследовали» | UPageHero, UButton |
| Дуэль | `#duel` | полоса «англицизм — аналог» для каждой пары, вкладки по группам А, Б, В | UPageSection, UTabs, UProgress |
| Словарь | `#dictionary` | поиск, фильтры, сортировка, сетка карточек; по клику — полная словарная статья | UInput, USelect, UCard, UBadge, USlideover |
| Грамматика | `#grammar` | таблица 15 глаголов с приставками, распределение приставок, факты о роде и склонении, графические варианты | UTable, UCard |
| Степень освоения | `#assimilation` | три колонки: освоенные (8), профессионализмы (25), частично освоенные (3) | UCard, UBadge |

## Данные

Все 36 слов лежат в готовом файле `words.json` (приложен к ТЗ), который кладётся в `app/data/words.json` без изменений. Цифры в файле совпадают с документом исследования: группы 14 / 10 / 12, степень освоения 8 / 25 / 3, 34 склоняемых слова, 15 глаголов с приставками.

Тип одного слова для `app/types/word.ts`:

```ts
export type Group = 'A' | 'B' | 'V'          // А — описательный аналог, Б — общеупотребительный, В — терминологический
export type Sphere = 'dev' | 'process' | 'general'
export type Assimilation = 'full' | 'professional' | 'partial'

export interface FrequencyPair {
  anglicism: number | null   // ipm или число вхождений; null — данных ещё нет
  analog: number | null
}

export interface Word {
  id: string                  // латиницей, для якорей: 'commit'
  word: string                // 'коммит'
  source: string              // 'commit'
  meaning: string
  etymology: string
  etymologyVerified: boolean  // сверено с Online Etymology Dictionary
  analog: string              // 'фиксация'
  group: Group
  sphere: Sphere
  assimilation: Assimilation
  gender: 'm' | 'f' | 'n'
  declinable: boolean
  verbs: { imperfective: string; perfective: string; prefix: string } | null
  derivatives: string[]       // 'релизный', 'бэкендер', 'легаси-код'
  variants: string[]          // другие написания: 'мердж'
  frequency: { ruscorpora: FrequencyPair; habr: FrequencyPair }
}
```

**Частоты пока пустые** (`null`): их внесут после подсчёта по НКРЯ и Хабру. Интерфейс обязан работать в обоих состояниях — это главное требование к данным.

**Подписи для интерфейса** хранятся в `app/utils/labels.ts`: группа А — «Описательный аналог», Б — «Общеупотребительный аналог», В — «Терминологический аналог»; сферы — «Разработка», «Командные процессы», «Общее»; степень освоения — «Освоенное», «Профессионализм», «Частично освоенное».

## Функциональные требования

Все цифры на странице вычисляются из `words.json`, а не пишутся вручную: если поменять данные, страница обновится сама. Логика подсчётов живёт в composable `app/composables/useWords.ts`.

**Главный экран**

- Ф1. Три цифры считаются из данных: всего слов, склоняемых (`declinable`), глаголов с приставками (`verbs !== null`).

**Дуэль**

- Ф2. Для каждой пары — полоса с долей англицизма: `anglicism / (anglicism + analog)`. Источник данных переключается «НКРЯ / Хабр»; переключатель виден, только если есть данные хотя бы по одному источнику.
- Ф3. Вердикт рядом с полосой текстом, не только цветом: 60% и выше — «Побеждает англицизм», 40% и ниже — «Побеждает аналог», иначе — «Паритет».
- Ф4. Если частот нет, полоса в нейтральном состоянии с подписью «Данные собираются», а над списком — прогноз для группы (А — побеждает англицизм; Б — аналог или паритет; В — в статьях аналог, в комментариях англицизм).
- Ф5. Вкладки «Все / А / Б / В» со счётчиком слов; клик по паре открывает словарную статью.

**Словарь**

- Ф6. Поиск по слову, английскому источнику, аналогу и вариантам написания; без учёта регистра, «ё» приравнивается к «е».
- Ф7. Фильтры: группа, степень освоения, сфера; кнопка «Сбросить»; счётчик «Найдено N из 36».
- Ф8. Сортировка: по алфавиту (по умолчанию, русская локаль), по группе, по степени освоения.
- Ф9. Поиск и фильтры записываются в адрес (`?q=коммит&group=V`), чтобы ссылкой можно было поделиться.
- Ф10. Карточка: слово, источник, аналог, значение, бейджи группы и степени освоения.
- Ф11. Пустой результат: текст «Ничего не нашлось» и кнопка «Сбросить фильтры».
- Ф12. Полная статья открывается в боковой панели: значение, происхождение с отметкой «сверено с Etymonline», аналог, род и склонение, глаголы, производные, варианты написания, частоты или «Данные собираются».
- Ф13. У каждой статьи свой адрес `#word-commit`: при открытии по такой ссылке статья открывается сразу.

**Грамматика, степень освоения, выводы**

- Ф14. Таблица 15 глаголов, сгруппированная по приставкам, и распределение приставок (за- 8, от- 3, с- 2, по- 1, про- 1) — считается из данных.
- Ф15. Факты о роде и склонении (32 мужского рода, 2 женского, 2 несклоняемых) и список 7 слов с вариантами написания.
- Ф16. Три колонки степени освоения; каждое слово — бейдж, по клику открывает статью.
- Ф17. Таблица проверки гипотезы по группам: слов в группе, с глаголами, доля (21% / 50% / 58%), плюс итоги исследования текстом.

**О проекте**

- Ф18. Цель, методы, список источников со ссылками, авторы `[ФИО авторов]`, ссылка на документ исследования `[ссылка]`.

## Дизайн и нефункциональные требования

Дизайн продолжает прототип словаря: два цвета кодируют две стороны дуэли — синий для англицизма, малиновый для русского аналога — и этот код одинаков во всех секциях.

**Дизайн**

- Цвета: палитры `anglo` (основа `#2E5BFF`) и `rus` (основа `#C0265A`) с оттенками 50–950 задаются в `main.css` через `@theme`; в `app.config.ts` — `primary: 'anglo'`, `secondary: 'rus'`, `neutral: 'slate'`.
- Шрифты: Unbounded 700 для заголовков, Golos Text 400/600 для текста.
- Заголовок главного экрана: «Баг» синим, «или» нейтральным, «ошибка?» малиновым — это легенда цветов для всей страницы.
- Одна анимация: полосы дуэли заполняются при первом появлении секции на экране; при `prefers-reduced-motion` — без анимации.

**Нефункциональные требования**

| Требование | Критерий |
| --- | --- |
| Адаптивность | корректно от 360 px; на телефоне карточки в одну колонку, подписи дуэли над полосой |
| Темы | светлая и тёмная, по умолчанию системная; обе проверены вручную |
| Доступность | контраст текста не ниже 4.5:1; всё доступно с клавиатуры; у полос `aria-label` вида «коммит 80%, фиксация 20%» |
| Скорость | Lighthouse (мобильный) не ниже 90 во всех четырёх категориях |
| Сборка | главная страница пререндерится (routeRules), на клиенте нет запросов к внешним API |
| SEO | `lang="ru"`, заголовок, описание и Open Graph через `useSeoMeta`, иконка сайта |
| Код | TypeScript в строгом режиме, `@nuxt/eslint` без ошибок, без `any`, компонент не длиннее \~200 строк |

## Разработка с Claude Code

Работать лучше пятью короткими этапами с проверкой после каждого, а не одним большим промптом: так проще ловить ошибки и откатываться через git.

**Подготовка**

1. Установить Node.js 22 LTS, pnpm, git и Claude Code; завести аккаунт на GitHub.
2. Создать пустую папку проекта, запустить в ней `claude` и подключить MCP Nuxt UI (команда в разделе «Стек и версии»).
3. Экспортировать этот документ в Markdown и положить в папку как `docs/TZ.md`, рядом — `words.json`.
4. Создать в корне `CLAUDE.md` с постоянными правилами:

```markdown
# Проект: словарь IT-англицизмов
- ТЗ: docs/TZ.md. Требования обозначены Ф1–Ф18, сверяйся с ними.
- Стек: Nuxt 4, Nuxt UI 4, TypeScript strict, pnpm.
- Документацию компонентов Nuxt UI бери из MCP nuxt-ui, не по памяти.
- Все цифры считаются из app/data/words.json, никакого хардкода.
- Интерфейс на русском. После каждого этапа: pnpm lint и pnpm typecheck.
```

**Этапы и промпты.** Перед сложными этапами включать режим планирования (Shift+Tab), чтобы Claude Code сначала показал план.

## Деплой на Vercel

Vercel разворачивает Nuxt без настройки: достаточно импортировать репозиторий с GitHub ([документация Vercel](https://vercel.com/docs/frameworks/full-stack/nuxt), [документация Nuxt](https://nuxt.com/deploy/vercel)). Сборку оставляем по умолчанию (`nuxt build`), а единственную страницу пререндерим, чтобы она отдавалась как готовый HTML.

1. В `nuxt.config.ts` добавить пререндер главной:

```ts
export default defineNuxtConfig({
  routeRules: {
    '/': { prerender: true }
  }
})
```

2. Создать репозиторий на GitHub и отправить в него код (`git push`).
3. На vercel.com: **Add New → Project → Import** нужного репозитория. Framework Preset определится как Nuxt автоматически; настройки сборки не менять.
4. Нажать **Deploy** и через 1–2 минуты получить адрес вида `имя-проекта.vercel.app`.
5. Дальше каждый `git push` в ветку `main` обновляет сайт, а другие ветки получают отдельные превью-ссылки.
6. Прописать итоговый адрес в `useSeoMeta` (`ogUrl`) и в разделе «О проекте».

Запасной путь без веб-интерфейса — Vercel CLI: `pnpm dlx vercel` для превью и `pnpm dlx vercel --prod` для продакшена.

## Критерии приёмки

Сайт принят, когда выполнены все пункты ниже на опубликованном адресе Vercel, а не только локально.

- [ ] Все требования Ф1–Ф18 работают; цифры на странице совпадают с документом исследования (36 слов, группы 14/10/12, степень освоения 8/25/3, 34 склоняемых, 15 глаголов, доли 21%/50%/58%).
- [ ] Тесты useWords проходят (`pnpm test`), `pnpm lint` и `pnpm typecheck` — без ошибок.
- [ ] С пустыми частотами дуэль показывает «Данные собираются» и прогнозы; если вписать в `words.json` тестовые частоты для двух пар, появляются полосы, проценты и вердикты.
- [ ] Поиск находит слово по варианту написания («мердж» → мерж) и по аналогу («отладка» → дебаг); «развертывание» и «развёртывание» дают одинаковый результат.
- [ ] Ссылка с фильтрами и ссылка `#word-commit` открываются в новой вкладке в том же состоянии.
- [ ] Страница корректна на телефоне шириной 360 px и на ноутбуке, в светлой и тёмной теме.
- [ ] Вся страница проходится с клавиатуры: Tab, Enter, Esc закрывает статью.
- [ ] Lighthouse (мобильный) — не ниже 90 во всех четырёх категориях.
- [ ] В разделе «О проекте» заполнены авторы и ссылки; плейсхолдеров в квадратных скобках не осталось.
